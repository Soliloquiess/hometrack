## 3. 개발 착수 전 반드시 고쳐야 할 것 3개

1. **마이홈 API 응답 스키마를 열람해 공고의 금액·면적 필드 유무를 확정한다.** (결함 #1, #3)
   이 결과에 따라 탭2 카드 구성과 신선도 바의 자동·반자동 표기가 달라진다. 없는 필드를 전제로 만들면 핵심 화면이 빈 카드로 채워진다. 조사서 A-3이 지목한 "붙임1. 요청 파라미터 코드(공공주택 모집공고)_260701.xlsx"를 여는 것이 유일한 확인 경로다.

2. **`policies.json`의 소득·자산·예비신혼 필드를 조사 결과에 맞게 확장하고, 탭1에 맞벌이 여부와 가구원수를 추가한다.** (결함 #2, #4, #5, #13, #14)
   이 넷은 한 덩어리다. 지금 스키마로는 정책 후보 8개 중 공급형 3개가 판정 불가이며, 2인 가구 기준액을 확보하지 못하면 예비신혼부부에게 가장 중요한 행복주택 판정이 아예 나오지 않는다.

3. **미검증 정책 수치로 "불가" 배지를 띄우지 못하게 막고, 민간 딥링크에서 예산을 뺀다.** (결함 #9, #6)
   전자는 사용자가 자격이 되는데도 신청을 포기하는 실손해 경로이고, 후자는 DESIGN.md가 절대 원칙으로 금지한 개인 조건의 URL 노출이다. 둘 다 코드 몇 줄이지만 명세에 없으면 개발자가 그대로 만든다.
