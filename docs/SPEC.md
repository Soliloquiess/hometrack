## 0. 지켜야 할 것 (기존 도구에서 검증된 원칙 — 어기지 말 것)

1. **외부 리소스 로드 금지.** CDN·웹폰트·이미지·지도 타일·분석 스크립트 전부 금지. 폰트는 시스템 폰트 스택.
   완성된 페이지의 네트워크 요청은 **0건**이어야 한다. GitHub Pages에 올려도 동일.
2. **파이썬/JS 라이브러리 의존 금지.** 수집기는 파이썬 표준 라이브러리, 화면은 순수 HTML+CSS+바닐라 JS.
3. **출처와 수집 시각을 항상 화면에 표시한다.** 출처마다 신선도가 다르다
   (시세 = 자동 / 마이홈 공고 = 스키마 확인 전까지 반자동 / **LH = 반자동(제목·유형·지역·공고상태·상세URL 은 자동, 금액·면적은 수동)** / 부산도시공사 = 수동 / 정책 = 반자동).
   이 비대칭을 숨기면 "낡은 화면을 최신으로 오인"하는 사고가 난다. 기존 도구에서 실제로 겪은 문제다.
   **확인되지 않은 출처를 "자동"으로 표시하지 않는다.**
4. **수집 실패를 조용히 넘기지 않는다.** 실패한 수집기는 화면에 실패로 표시하고 "새 소식" 탭에 남긴다.
   공공 사이트 개편으로 수집이 깨지는 것은 예외가 아니라 예정된 일이다.
   실패 시 **직전 성공 데이터를 그대로 보여주되, 그 데이터의 수집 시각을 함께 표시**한다.
5. **개인 조건은 서버로도 URL로도 나가지 않는다.** 소득·자산·대출가능액·혼인예정일 등 입력값은 **localStorage 전용**.
   `data/*.json`·빌드 산출물·저장소·**외부 링크의 URL 파라미터** 어디에도 넣지 않는다(`DESIGN.md` §0-3).
6. **실거래가는 "과거 계약"이지 "지금 살 수 있는 매물"이 아니다.** 이 문장을 시세가 보이는 모든 화면에 명시한다.
   임대차 신고제(2021.6~)로 부산도 신고 대상이나 **신고 지연이 최대 30일** 있고,
   **신고 의무 금액 하한 미만 계약은 통계에서 빠질 수 있다**(하한값 미확인 — §8 참조). 이 두 가지를 시세 블록 주석에 함께 적는다.
7. **민간 매물은 수집하지 않는다.** 네이버부동산·직방·다방은 공식 API가 없고 이용약관이 크롤링을 금지한다.
   대신 **역·거래유형만 걸린 검색 링크**를 제공한다. 금액은 넣지 않는다(원칙 5).
8. **정책 수치를 화면 코드에 하드코딩하지 않는다.** 소득 기준·한도·금리는 매년 바뀐다.
   전부 `policies.json`·`income_tables.json` 필드로 관리하고, 근거·출처·확인일자·신뢰도를 함께 적는다.
9. **검증되지 않은 수치로 사용자를 탈락시키지 않는다.** `confidence`가 `official`이 아닌 정책은
   어떤 경우에도 **"불가" 배지를 띄우지 않는다.** 자격이 되는데 신청을 포기하게 만드는 것이 이 도구의 최대 실패다.
   **v1.2 확장** — `pending_change`(발표됐으나 시행 미확인인 기준 변경)가 달린 정책은 `official` 이어도
   **소득 기준 초과로 인한 "불가"를 내지 않고 `조건부 — 기준 완화 예정(확정 시 갱신)` 으로 강등한다**(§3-2, D3).
   완화가 예고된 수치로 탈락시키는 것은 낡은 값으로 탈락시키는 것과 같다.
10. **인쇄 가능해야 한다.** `@media print` 필수. 추천 목록·정책 표는 PDF로 뽑아 둘이 같이 본다(`DESIGN.md` §0-2).

## 1. 디자인 — svntrack 앱 셸을 상속한다

새로 발명하지 말 것. 토큰의 **이름과 값**은 루트 `DESIGN.md` §1 이 정본이다. 새 팔레트를 만들지 않는다.

**토큰 목록**
`--bg --bg-2 --bg-3 --bg-sunk --fg --fg-2 --fg-3 --line --line-2 --accent --accent-bg --radius --sans --mono --shadow`
+ 심각도 `--hi --hi-bg --mid --mid-bg --low --low-bg`
+ 변경 표시 `--add-bg --add-fg --del-bg --del-fg`

토큰 의미를 이 프로젝트에서 다음과 같이 고정한다.

| 토큰 | 의미 |
|---|---|
| `--hi` | 자격 불가 / **D-day 7일 이내** / 수집 실패 |
| `--mid` | 조건부 / **D-day 30일 이내** / 표본 부족(5건 미만) / 정책 확인일 90일 초과 |
| `--low` | 자격 해당 / 예산 내 / 정상 수집 |
| `--add-*` | 새 소식 — 신규 공고 |
| `--del-*` | 새 소식 — 마감·삭제 |

D-day 임계는 **7일 / 30일**이다(`DESIGN.md` §3). 공고 접수기간은 보통 1주 이상이라 D-3 기준은 경고가 늦다.
마감 지난 공고는 목록에서 접되 **삭제하지 않는다**(새 소식에서 참조).

**테마 3상태 처리 (필수)**
- 기본 `:root` = 라이트 팔레트 전량 정의
- `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { ... } }` = 토큰만 재정의
- `:root[data-theme="dark"] { ... }` = 토큰만 재정의
- 색은 **반드시 토큰 경유**. 미디어쿼리·속성선택자 블록 안에서만 정의된 색이 있으면 안 됨. 색 리터럴 하드코딩 0건
- `body` 에 토큰 배경 명시
- 테마 토글은 svntrack 방식 그대로: `<head>` 최상단 인라인 스크립트가
  `localStorage["hmt.theme"]` 를 읽어 CSS 칠해지기 전에 `data-theme` 를 건다 (다크 사용자 흰 화면 번쩍임 방지)

**셸 구조**
```
header.topbar : .brand(home track) + nav(탭 5개) + .topbar-right(수집 시각 + 테마 토글)
main.wrap     : 신선도 바 → 탭별 콘텐츠
```
탭 전환은 페이지 이동이 아니라 **단일 파일 내 JS 전환**(`hidden` 토글 + `location.hash`).
새로고침·뒤로가기에도 탭이 유지되어야 한다.
탭 링크는 **`<a href="#...">` 를 유지하고 `aria-controls` 를 추가한다**(D22).
`<a href>` + `:focus-visible` 로 키보드 전환·포커스 표시는 이미 충족되므로 ARIA tabs 롤 전체를 구현하지 않는다 — 대상 패널만 연결한다.

**레이아웃**: `.wrap` **max-width 1100px** (`DESIGN.md` §2). 넓은 표는 각자 `overflow-x:auto` 컨테이너 안에서 스크롤. body 가로 스크롤 금지. 표 세로선 0건.
**타이포**: 시스템 폰트만. body 14px/1.55, h1 20px, h2 14px `--fg-2`. 금액·건수는 `--mono` + `tabular-nums` + 우측 정렬.
**금액 표기**: 만원 단위 한글 혼용(`1억 8,000만원`).
**차트**: 인라인 SVG만. 외부 차트 라이브러리 금지. 지도 타일 금지 → 역 순서는 **1호선 노선도식 가로 띠**로 표현.
**375px**: 탭은 가로 스크롤, 카드 세로 스택, 표는 컨테이너 안에서 가로 스크롤. 전 탭이 읽혀야 한다.
**인쇄 (`@media print`)**: 상단바·입력 폼·테마 토글·필터 숨김, 접힌 공고·정책 펼침, 링크는 URL 병기, 배경색 대신 테두리로 구분.

### 공통 — 신선도 바 (모든 탭 상단 고정)

**출처별로 한 줄씩** 낸다. 묶어서 "공공 공고 · 자동" 으로 표시하면 원칙 3을 스스로 어긴다.
각 줄에 **출처 / 마지막 성공 수집 시각 / 자동·반자동·수동 태그 / 상태**.
태그는 `meta.collectors[].kind` 값을 **그대로** 표시한다. 화면에서 임의로 승격하지 않는다.

| 민간 매물 | 수집하지 않음 | — | 회색 고정 `수집 안 함 — 검색 링크만 제공` |

- 어느 줄이든 수집 실패면 그 줄이 `--hi` 로 바뀌고, **직전 성공 시각과 실패 사유**를 같이 적는다.

- 시세 줄에는 항상 **"실거래 = 과거 계약 기록. 신고 지연 최대 30일"** 주석을 단다.
- **LH 줄은 "제목·유형·지역·공고상태·상세URL 은 자동, 금액·면적은 수동"임을 한 줄로 밝힌다**(D1).
  분양임대공고문 조회 서비스(15058530)는 `PAN_NM`(공고명)·`AIS_TP_CD_NM`(세부유형)·`CNP_CD_NM`(지역명)·`PAN_SS`(공고상태)·`DTL_URL`(상세 URL)을 **정형 필드로** 준다.
  그러나 **보증금·월임대료·전용면적은 짝 API "분양임대공고별 상세정보 조회"(15057999)의 응답 스키마를 실호출로 확인한 뒤에 결정한다**
  (`DATA_SOURCES` §E 참조 — 확인 전까지 미확정). 확인 전까지 LH 태그는 **반자동**이고 금액·면적은 `notices_manual.json` 수동 상세에만 의존한다.
  "자동"이라고만 적으면 사용자가 금액까지 최신인 줄 오인한다. 원칙 3이 막으려는 바로 그 사고다.

**필수 입력**

| 항목 | 형식 | 쓰임 |
|---|---|---|
| 순자산 | 만원 | 버팀목·디딤돌·신생아특례 자산 기준 |
| 총자산 | 만원 | 행복주택·국민임대·통합공공임대 자산 기준 |
| 자동차 가액 | 만원 | 유형별 한도가 다름(행복주택 ↔ 국민임대) |
| 청약통장 가입 | 개월 + 납입 회차 | 국민임대·통합공공임대 요건 |

**상태**
- **저장**: 입력 즉시 `localStorage["hmt.cond"]` 에 저장. 저장 버튼 없음. 저장 시각을 옆에 표시.
- **빈 상태**: 최초 진입 시 전 항목 비어 있고, 상단에 "입력값은 이 브라우저에만 저장되고 어디에도 전송되지 않습니다" 고지.
- **localStorage 차단 환경**: 저장 실패해도 화면은 정상 렌더되고, 세션 내에서는 메모리로 동작한다.
  "이 브라우저에서 저장이 차단되어 새로고침 시 초기화됩니다" 안내를 띄운다. **에러로 죽지 않는다.**
- **초기화 버튼**: 저장값 전체 삭제. 삭제 전 확인.
- **인쇄 시 이 탭 전체를 숨긴다**(개인 조건이 종이에 남지 않게).

**인터랙션**: 값을 바꾸면 다른 탭의 배지 숫자(추천 건수·해당 정책 수)가 즉시 갱신된다.

### 탭 2 — 추천 주거 (`#homes`) ★ 핵심 화면

**2-1. 상단 고정 섹션 — 신규 · 마감 임박**

지역 필터를 걸면 대부분의 날에 신규 공고가 0건일 수 있다. 그래도 **매일 열 이유가 남아야 한다.**
목록보다 위에 항상 이 두 블록을 고정 배치한다.

- `신규` — **`notices[].first_seen` 이 최근 7일 이내**인 공고 (`--add-*`).
  하루치 `diff.new_notices` 로는 7일 창을 만들 수 없어 `first_seen` 을 정식 필드로 둔다(§3-6, D8)
- `마감 임박` — **오늘 기준으로 재계산한 D-30 이내 전체**. D-7 이내 (`--hi`) / D-30 이내 (`--mid`)
- 두 블록 모두 0건이면 "이번 주 신규·마감 임박 공고 없음" 한 줄로 접는다. 블록 자체를 숨기지 않는다.
- **마감 임박의 정본은 두 곳으로 갈린다**(D12). 이 블록 = 현재 D-30 이내 **전체**(매일 재계산),
  탭 5 = 이번 수집에서 **새로** D-30/D-7 안으로 들어온 것(`diff.closing_soon`).
  **두 화면의 건수가 다른 것은 모순이 아니다.** 각 블록 캡션에 무엇을 세는지 한 줄로 적는다.
- 접수기간이 없는 공고(`apply_end == null`)는 **D-day 를 계산하지 않는다.** `null` 을 0 이나 임박으로 취급하지 않는다(D12).

**2-2. 공고 카드 필드**

| 필드 | 내용 | null 허용 |
|---|---|---|
| 제목 | 공고명 | 아니오 |
| 공급유형 | 행복주택 / 국민임대 / 통합공공임대 / 매입임대 / 전세임대 등 | 예 → `유형 미표기` |
| 지역 | 구 + 법정동 | 동은 예 |
| 자격 매칭 | **해당 / 조건부 / 불가** 배지 + **판정 사유 한 줄**(§3-2 규칙) | 아니오 |
| 접수기간 | `MM/DD ~ MM/DD` + **D-day 배지** | 예 → `접수기간 미표기` |
| 임대보증금 / 월임대료 | 만원. 범위면 최소~최대 | **예** → `공고문 확인 필요` |
| 전용면적 | ㎡ | **예** → 미표기 |
| 기준역까지 | `{기준역}에서 N정거장` (같은 역이면 `기준역`). **데이터에 굽지 않고 `meta.config.stations[]` 순서 인덱스 차로 화면이 계산한다**(D18) | 예 → `역 매핑 없음` |
| 원문 | 출처 사이트 원문 링크 (새 창, `rel="noopener noreferrer"`) | 아니오 |
| 출처·수집 | 출처명 + 자동/수동 태그 + 수집 시각 | 아니오 |

> **금액·면적이 `null` 인 공고가 정상 케이스다.** 조사 결과 공고 API가 금액·면적을 제공하는지 확인되지 않았고,
> 다수는 공고문 PDF 본문에만 있을 가능성이 크다. 빈 값을 오류로 취급하지 말고 `공고문 확인 필요` 로 표기한다.

> **LH 출처 공고는 상세 API 스키마 확인 전까지 `detail_level: "meta_only"` 를 유지한다**(D1).
> 분양임대공고문 조회 서비스(15058530)가 주는 제목·세부유형·지역명·공고상태·상세URL은 자동으로 채워지지만(**접수기간은 응답에 없어 null** — `PAN_SS` 상태값만 온다),
> **보증금·월임대료·전용면적은 상세 API(15057999) 응답에 해당 필드가 있는지 확인되지 않았다**(`DATA_SOURCES` §E).
> 따라서 이 카드는 `상세 미수집` 배지를 달고 **금액 미표기 섹션**에 들어간다.
> 사람이 `notices_manual.json` 에 상세를 채우거나 **상세 API에 금액 필드가 확인되면** `detailed` 로 승격되어 예산 판정 대상이 된다.

**2-3. 목록 구성**

공고를 3개 묶음으로 나눈다. 예산 판정 규칙은 §3-1.

1. **예산 내** — 금액이 있고 예산 안에 드는 공고. `전 평형 가능` / `일부 평형 가능` 2단 표기
2. **금액 미표기** — 금액이 `null` 이라 판정할 수 없는 공고. **접어두지 않고 별도 섹션으로 보여준다**(판정 불가지 탈락이 아님)
3. **예산 밖** — `예산 밖 N건 접힘` **한 줄로만**. 카드를 그리지 않는다(`DESIGN.md` §3)

- 기본 정렬: **접수 마감 임박순**. 마감된 공고는 접힘.
- 좌측 사이드 필터: 공급유형 / 역 / 자격(해당만) / 지역(13역 인근만 ↔ 부산 전역) / 마감 포함
  (svntrack `.side-block` `.seg` `.facet` 패턴 재사용)
- **지역 필터 기본값은 "13역 인근"이되, 그 결과가 0건이면 자동으로 "부산 전역" 결과 건수를 안내한다.**

**2-4. 시세 근거 블록**

선택한 역들의 실거래 요약. 주택유형 기본값 **아파트**, 거래유형 기본값 **전세**.
```
구서역 · 아파트 · 전세 · 최근 12개월
계약 42건 · 중위 1억 9,500만원 · 내 예산(2억 1,000만원) 이내 61%
※ 500만원 버킷 기준 · 과거 계약 통계이며 매물이 아닙니다. 신고 지연 최대 30일.
```
- `이내 N%` 는 `deposit_hist` 로 계산한다(§3-1, D6). **분위수 근사로 만든 값을 확정값처럼 쓰지 않는다.**
  버킷 폭을 캡션에 밝혀 해상도 한계를 드러낸다.
- 표본이 `sample_min`(5건) 미만이면 중위값을 숫자로 내세우지 않고 `표본 부족(N건)` 으로 표시한다(`--mid`).
- 표본 0건이면 `해당 기간 신고된 계약 없음`.

**2-5. 민간 매물 검색 링크**

목록 하단. **역명과 거래유형만** 담은 검색 링크를 네이버부동산 / 직방 / 다방 각 1개 생성한다.

- **보증금·월세·소득 등 입력값은 URL에 넣지 않는다**(원칙 5, `DESIGN.md` §0-3).
- 모든 외부 링크에 `rel="noopener noreferrer"` + `referrerpolicy="no-referrer"` 를 건다(Referer로 Pages 주소가 새는 것 차단).
- "여기서부터는 직접 확인하세요. 이 도구는 민간 매물을 수집하지 않습니다." 명시.

**2-6. 빈 상태 3종을 구분한다**
1. 조건 미입력 → "조건 입력 탭에서 예산을 먼저 넣으세요"
2. 조건은 있는데 결과 0건 → "예산 범위 안 공고가 지금은 없습니다" + 예산을 얼마 올리면 N건이 들어오는지 한 줄 힌트
3. 수집 실패 → "공고 수집이 실패했습니다(사유). 아래는 YYYY-MM-DD 수집분입니다" + 이전 데이터 표시

### 탭 3 — 정책·지원 (`#policy`)

입력값으로 자격을 자동 대조해 **해당 / 조건부 / 불가** 3단으로 분류한다.

**분류 규칙**

| 판정 | 조건 |
|---|---|
| **해당** | `confidence == "official"` **이고** 판정에 필요한 입력값이 전부 있고 전 기준을 충족 |
| **조건부** | 충족하지만 판정에 필요한 값이 미입력 / 추가 확인 필요 / **`confidence != "official"`** |
| **불가** | `confidence == "official"` **이고** 명시적으로 기준을 벗어남 (소득 초과, **혼인 기간 초과**, 유주택 등). 단 아래 게이트 3종에 걸리면 조건부로 강등 |

**"불가 → 조건부" 강등 게이트 3종** — 결합 규칙과 사유 문구는 §3-2 (D11) 에서 정의한다.

| # | 게이트 | 강등 후 사유 · 배지 |
|---|---|---|
| 1 | `confidence != "official"` | `조건부 — 수치 미검증(2차 자료 기준). 공고문 확인 필요` + `미검증` 배지 |
| 2 | `pending_change` 있음 **이고** 불가 사유가 **소득 기준 초과** | `조건부 — 기준 완화 예정(확정 시 갱신)` + `완화 예정` 배지 (D3) |
| 3 | 기준액이 폴백 **근사값** | `조건부 — 기준액 근사값(공표표에 해당 비율 없음). 공고문·기관 확인 필요` + `근사값` 배지 |

> 🔴 **`confidence`가 `official` 이 아닌 정책은 어떤 값이 들어와도 "불가"를 띄우지 않는다.**
> 대신 `조건부 — 수치 미검증(2차 자료 기준). 공고문 확인 필요` 로 강등하고 카드에 `미검증` 배지를 단다.
> 검증되지 않은 숫자로 사용자가 신청을 포기하면 실손해가 발생한다(검수 #9).

> 🔴 **`pending_change` — 기준 완화가 예고된 정책** (D3).
> 발표는 됐으나 **시행이 확인되지 않은** 기준 변경이 있는 정책에 붙는다. **현행 수치는 바꾸지 않는다.**
> 카드에 `완화 예정` 배지 + `pending_change.summary` 한 줄 + `source_url` 링크를 노출하고,
> `effective` 가 `"unknown"` 이면 "시행 시점 미확정"을 함께 적는다.
> 시행이 확인되면 연구자가 값을 갱신하고 `pending_change` 를 제거한다. 그때까지 이 정책은 소득 초과로 사용자를 탈락시키지 않는다.

**세 분류 모두 "왜 그렇게 판정됐는지"를 한 줄로 적는다.** 사유 없는 배지는 쓸모없다.
예: `조건부 — 총자산 미입력`, `조건부 — 2인 가구 소득 기준액 미확보`, `불가 — 부부 합산 소득이 기준 초과(7,500만원)`

**정책 카드 필드**: 정책명 / 제공기관 / 유형(공급·대출·이자지원) / 자격 판정 + 사유 /
혜택 요약(한도·금리) / 적용된 기준값과 그 출처 링크 + **적용비율(가구원수 가산이 반영된 값)** + `year_label` /
**최종 확인일** / `confidence` 배지 / `수동 정리` 배지 / (있으면) **`완화 예정` 배지 + `pending_change.summary` 한 줄**

**정책 후보 (v1 수록 대상)**
행복주택(신혼·예비신혼) / 국민임대 신혼 우선공급 / 통합공공임대 신혼 우선공급 /
신혼부부 버팀목 전세자금대출 / 신혼부부 디딤돌 / 신생아 특례대출 /
부산시 신혼부부 주택융자·대출이자 지원 / 부산시 럭키7하우스

> **자격 수치는 이 명세에 박지 않는다.** 전부 `policies.json`·`income_tables.json` 으로 관리하며,
> 조사 근거는 `docs/DATA_SOURCES.md` 에 둔다. 수치는 매년 바뀌고, 바뀔 때 명세를 고치면 안 되기 때문이다.

**신선도 경고**: 정책은 수동 정리분이다. **최종 확인일이 90일을 넘으면** 카드에 `--mid` 경고.
출처 페이지 변경이 감지되면 `--hi` + "출처 페이지가 바뀌었습니다. 재확인 필요".

**고정 고지**: 탭 상단에 "예비신혼부부 인정 조건은 정책마다 다릅니다(혼인계획 증빙·혼인예정 3개월 등).
정확한 조건은 해당 공고문·상품설명서를 확인하세요." 를 항상 표시한다(`DATA_SOURCES` §C-3).

### 탭 4 — 역별 비교 (`#stations`)

13개 역을 한 표에서 비교한다. "어느 역이 우리 예산에 현실적인가"를 답하는 화면.
상단에 **1호선 노선도식 가로 띠**로 역 순서를 표시하고, 기준역을 강조한다(지도 타일 금지).

| 열 | 내용 |
|---|---|
| 역 | 역명 + 소속 구 |
| 기준역까지 | `N정거장` — `meta.config.stations[]` 순서 인덱스 차로 **화면이 계산한다**(D18). 기준역을 탭1에서 바꾸면 즉시 다시 계산된다 |
| 매핑 법정동 | 개수 + 펼치면 목록 |
| 전세 중위 | 만원 (표본 건수 병기) |
| 예산 내 비율 | % + 막대. **`deposit_hist` 로 계산한다**(§3-1, D6). 캡션에 `500만원 버킷 기준` 표기 |
| 월세 중위 | 보증금 / 월세 |
| 진행 중 공고 | 건수 (0이면 회색) |

- **주택유형 선택(아파트/연립다세대/오피스텔)을 표 상단에 둔다. 기본값 아파트.** 유형을 섞은 중위값은 만들지 않는다.
- 기본 정렬: **예산 내 비율 내림차순**. 기준역 행은 항상 강조 표시.
- 표본 `sample_min` 미만 역은 수치를 `--mid` 로 흐리게 하고 `표본 N건` 을 붙인다. 숨기지는 않는다.
- 행 클릭 시 펼침: 매핑된 법정동 목록, **최근 `trend_months`(기본 3개월) 월별 중위값 추세 라인**(인라인 SVG).
- 표 상단 주석: "정거장 수는 1호선 기준 정차 역 수이며 환승·도보 시간은 포함하지 않습니다."

### 탭 5 — 새 소식 (`#news`)

**직전 수집분 대비 diff.** 비교 기준과 보관 위치는 §3-5에 고정 정의한다.

표시 항목 5종, 각각 건수 배지와 함께 섹션으로 나눈다.
1. **신규 공고** — 직전 수집에 없던 공고 (`--add-*`, 자격 판정 배지 포함)
2. **마감 임박** — 이번 수집에서 **새로** D-30/D-7 안으로 들어온 공고(`diff.closing_soon`). D-7 이내 (`--hi`) / D-30 이내 (`--mid`).
   **`closing_soon[].dday` 를 화면에 그대로 표시한다.** 탭 2 의 고정 섹션(현재 D-30 전체)과 건수가 다를 수 있고, 그것은 모순이 아니다(D12)
3. **마감됨** — 접수 종료된 공고 (`--del-*`). `apply_end < today` **또는** 출처 목록에서 사라진 공고(§3-5, D12).
   사라진 경우(`disappeared: true`)는 `출처 목록에서 사라짐(마감 추정)` 으로 문구를 구분한다
4. **정책 변경 감지** — 출처 페이지 본문이 바뀐 정책. 무엇이 바뀌었는지는 **사람이 확인해야 함**을 명시
5. **수집 실패** — 실패한 수집기 / 사유 / 마지막 성공 시각

- 기본은 **오늘 diff**(화면 데이터 키 `diff`). `diff_history.json` 의 최근 14일치는 화면 데이터 키 `diff_history` **배열**로 실어 날짜별로 접어서 아래에 둔다(D21).
- 변화가 하나도 없으면 "직전 수집과 달라진 것이 없습니다" 빈 상태 + 마지막 수집 시각.
- **첫 실행(`is_first_run: true`)** 은 diff 대신 "첫 수집입니다. 다음 수집부터 변경분을 표시합니다" 를 보여준다.

| `sample_min` | **5** | 표본 부족 판정 하한 |
| `banjeonse_ratio` | **240** | 반전세 분류 배수 (§3-3). 출처 확정 전까지의 설정값 |
| `notice_retain_days` | **60** | 출처 목록에서 소멸(`disappeared`)한 공고를 `notices.json` 에 보존하는 일수. 지나면 제거(새 소식 이력은 `diff_history` 에 남음) |

`config.json` 은 위 수치 외에 **`stations[]`**(1호선 순서 · 역↔법정동 매핑 · §3-6 `meta.config.stations` 로 복사),
**`exclusion_rules[]`**(§3-2, D19), **공급유형 → 정책 매핑표**(§3-2 `linked_policy_id` 자동 부여)를 갖는다.

**실거래 계약 단건 판정**
```
가용액 = 보증금가용액 + 대출가능액

전세 : 계약보증금 <= 가용액
월세 : 계약보증금 <= 가용액  AND  계약월세 <= 월세상한   (두 축 모두 충족)
```

**공고 판정 — 보증금·월임대료 두 축을 항상 적용한다** (D9)

🔴 **사용자의 거래유형 선택(전세/월세)과 무관하게 두 축을 모두 판정한다.**
공공임대 공고는 대부분 보증금 + 월임대료가 함께 붙는다. 거래유형 선택을 게이트로 걸면 기본 상태(전세만 선택)에서
**월세 축이 통째로 꺼져** 월임대료가 상한을 넘는 공고가 "전 평형 가능"으로 나온다.

*보증금 축* — `가용액 = 보증금가용액 + 대출가능액`

| 조건 | 표기 |
|---|---|
| `deposit_min == null` | **판정 없음** → `금액 미표기` 섹션 + `공고문 확인 필요`. **상한이 있어도 판정하지 않는다**(D10). 하한을 모르는 공고를 예산 밖으로 접어 감추면 안 된다 |
| `deposit_min` 있음 · `deposit_max == null` | **하한으로만 판정** (`deposit_min <= 가용액` → 가능 / 초과 → 예산 밖) + 사유에 **`상한 미표기`** 명기 (D10) |
| `deposit_max <= 가용액` | **전 평형 가능** (`--low`) |
| `deposit_min <= 가용액 < deposit_max` | **일부 평형 가능** (`--low`, 사유에 "일부 평형" 명기) |
| `deposit_min > 가용액` | **예산 밖** → 목록에 그리지 않고 접힌 줄로만 |

*월임대료 축* — `월세상한` = 탭1 입력

| 조건 | 표기 |
|---|---|
| `rent_min == null` | 이 축은 **판정 없음**. 사유에 `월임대료 미표기` |
| 월세 상한 **미입력** | 이 축은 **판정 없음**. 보증금 축 결과만 쓰고 사유에 **`월임대료 상한 미입력`** 을 명기한다 (D9) |
| `rent_max <= 월세상한` | **전 평형 가능** |
| `rent_min <= 월세상한 < rent_max` | **일부 평형 가능** |
| `rent_min > 월세상한` | **예산 밖** |

*두 축의 결합* — 등급을 `전 평형 가능 > 일부 평형 가능 > 예산 밖` 으로 두고 **둘 중 낮은 등급**을 공고의 최종 예산 판정으로 쓴다.
한쪽이 `판정 없음` 이면 나머지 한 축의 등급을 그대로 쓰고, **두 축 모두 `판정 없음` 이면 `금액 미표기`** 다.
사유에는 두 축의 근거를 모두 적는다. 예: `일부 평형 가능 — 보증금 전 평형 / 월임대료 일부 평형(28~35만원, 상한 30만원)`.

**전월세 상호 환산** (다른 거래유형끼리 비교할 때만 사용)
```
전세환산액 = 보증금 + (월세 * 12 / conversion_rate * 100)
```
환산으로 계산된 값은 화면에서 **`환산` 배지**를 붙여 실제 계약금액과 구분한다. 섞어서 보여주면 안 된다.

**예산 내 비율** (D6)

정의는 `비율 = (기간 내 예산 내 계약 건수) / (기간 내 전체 계약 건수)` 다.
예산은 브라우저에만 있으므로(원칙 5) `collect.py` 가 미리 셀 수 없다. 그래서 **보증금 히스토그램**을 실어 브라우저에서 계산한다.

`trades.aggregates[].deposit_hist: [{lo, hi, count}]` — 만원 단위, 버킷 폭 `deposit_hist_bucket`(기본 **500만원**),
`lo` 오름차순, 마지막 버킷은 `hi: null` 로 개방한다.

```
비율 = ( Σ count[hi <= 가용액]  +  가용액이 걸친 버킷의 선형 비례분 ) / count

걸친 버킷 b (b.lo <= 가용액 < b.hi) 의 비례분 = b.count × (가용액 − b.lo) / (b.hi − b.lo)
마지막 개방 버킷(hi = null)에 걸리면 비례분은 0 으로 둔다 — 상한을 모르므로 올려 세지 않는다
```

- 🔴 **분위수(p25/p50/p75)로 CDF 를 근사하지 않는다.** 조각선형 보간 계수(1.6 / 0.02 / 0.98 같은 값)를 코드에 박는 순간
  그 근사값이 `내 예산 이내 61%` 라는 **확정값처럼** 화면에 남는다. 근사를 쓸 거라면 화면에 근사임을 밝혀야 하는데,
  히스토그램을 실으면 그럴 필요 자체가 없어진다.
- 화면 캡션에 **`500만원 버킷 기준`**(적용값 표기)을 붙인다. 버킷 폭만큼의 해상도 한계가 있음을 밝히는 것이다.
- 분모가 `sample_min` 미만이면 비율을 계산하지 않고 `표본 부족` 으로 표시한다.
- 같은 히스토그램을 탭2 시세 근거 블록과 탭4 `예산 내 비율` 열이 **공유한다.** 두 화면이 다른 방식으로 계산하면 안 된다.

**매매**: v1에서 판정하지 않는다. 입력 항목 자체를 노출하지 않는다.

### 3-2. 자격 판정 로직

**공고 자격 판정**

`notices.json` 에는 **소득·자산 기준 필드가 없다.** 공고 API가 주지 않기 때문이다.
따라서 공고만 보고는 "해당" 판정에 필요한 소득·자산 대조를 할 수 없고,
규칙을 그대로 두면 **모든 공고가 조건부로 떨어져 판정 기능 자체가 무의미해진다.**
이 공백을 **정책 판정 승계**로 메운다.

**`linked_policy_id`** (`string|null`, 선택 필드) — 그 공고가 어느 정책의 자격 기준을 따르는지 가리킨다.
예: 행복주택 공고 → `policies.json` 의 행복주택 항목.
값은 사람이 `notices_manual.json` 에서 지정하거나, **공급유형 → 정책 매핑표**(`config.json`)로 자동 부여한다.

| 조건 | 공고 판정 |
|---|---|
| 공고 원문 `exclusions` 에 걸림 (예: 유주택자 제외 + 무주택 "아니오") | **불가** |
| `linked_policy_id` 있음 + 연결 정책 판정이 **해당** | **해당** (승계) |
| `linked_policy_id` 있음 + 연결 정책 판정이 **조건부** | **조건부** (승계) |
| `linked_policy_id` 있음 + 연결 정책 판정이 **불가** | 🔴 **조건부** — 불가는 **승계하지 않는다** |
| `linked_policy_id` 가 `null` | **조건부** — 자격 대조 정보 없음 |
| `linked_policy_id` 가 있으나 그 id 의 정책이 `policies.json` 에 **없음**(dangling) | **조건부** — 사유는 `연결 정책({id})을 찾을 수 없음 — 설정 오류` (D20). `null` 과 문구를 **구분한다** |

🔴 **정책의 "불가"를 공고로 승계하지 않는 이유.**
공고마다 소득·자산 기준이 본 정책과 다를 수 있고(회차별 완화, 우선공급 별도 기준),
연결 자체가 사람이 붙인 **추정**이다. **추정 위에 얹은 탈락 판정은 근거가 두 겹으로 약하다.**
자격이 되는데 신청을 포기하게 만드는 것이 이 도구의 최대 실패다(원칙 9).
공고에서 "불가"를 낼 수 있는 근거는 `exclusions` 하나뿐이다. 그건 공고 원문 자체가 근거다.

**승계 시 어느 정책에서 온 판정인지를 사유 텍스트에 반드시 적는다.**
- `해당 — 자격 기준 충족 (연결 정책: 행복주택)`
- `조건부 — 연결 정책 자격 미충족 (행복주택: 소득 기준 초과). 공고 기준은 다를 수 있으니 공고문 확인`
- `조건부 — 연결 정책 판정에 총자산 미입력 (행복주택)`
- `조건부 — 연결된 정책 없음. 자격 대조 정보 없음`
- `불가 — 공고 명시 배제 조건: 유주택자 제외`

- `target_groups` 는 **표시용**이다. 원문 대상 표기를 화면에 그대로 보여주되, 판정 근거로는 `linked_policy_id` 를 우선한다.
  대상 표기는 있는데 연결 정책이 없으면 사유에 `대상 표기는 있으나 기준 대조 불가` 로 적는다.
- `target_groups` 가 비어 있어도 **불가가 아니라 조건부**다. 정보 부재를 탈락으로 처리하지 않는다.
- 문자열 매칭은 정규화(공백 제거) 후 부분일치. **매칭 규칙표는 `config.exclusion_rules` 로 뺀다**(D19).
  `exclusion_rules: [ { keyword: string, input: "noHome"|"householder"|…, match: "contains" } ]` —
  `keyword` 가 공고 `exclusions` 원문에 부분일치하고 **그 `input` 축의 사용자 입력이 배제 조건에 해당할 때만 "불가"** 다.
  키워드를 화면 코드에 하드코딩하지 않는다(원칙 8). 대조 축이 하나뿐이면 다른 배제 조건이 조용히 무시된다.
  **이 표에 매칭되지 않은 `exclusions` 항목은 표시만 하고 판정에 쓰지 않는다.** 공고가 "불가"를 낼 근거는 이 표에 매칭된 `exclusions` 뿐이다.
- **`build.py` 는 `linked_policy_id` 참조를 검증한다.** dangling 이면 **경고를 로그에 남기되 빌드는 계속한다**(D20).
  화면은 위 표의 dangling 사유를 표시해 매핑 오타가 `null` 로 위장되지 않게 한다.
- 연결 정책의 `confidence` 가 `official` 이 아니면 승계된 판정에도 `미검증` 배지를 함께 단다(원칙 9).

**정책 소득 판정**

`policies.json` 의 `income.basis` 에 따라 판정식이 갈린다.

**적용비율 = (맞벌이면 `pct_dual` else `pct`) + `pct_adjust_by_household[가구원수]`** — 키가 없으면 가산 0 (D2)

| `basis` | 판정식 |
|---|---|
| `urban_worker_pct` | 위 **적용비율**로 기준액 = `income_tables.urban_worker.by_household[가구원수][적용비율]` **표에서 직접 조회** → **월평균 소득(연소득÷12) ≤ 기준액** |
| `median_pct` | 위와 동일하되 `income_tables.median_income` 표를 본다 |
| `annual_krw` | **부부 합산 연소득 ≤ `income.amount`** |

🔴 **가구원수 가산을 빼먹으면 이 도구의 기본 사용자에게 잘못된 "불가"가 난다**(D2).
공급형 정책의 공식 원문은 "계층별 소득기준에 **1인 가구 20%p, 2인 가구 10%p 각각 가산**"이다.
`policies.criteria.income.pct_adjust_by_household` (예: `{"1": 20, "2": 10}`) 는 **가구원수 → 가산 %p** 표이며 값은 `policies.json` 이 갖는다.
표 조회는 **가산이 반영된 적용비율 키로** 한다 — 예: 가구원수 2 · 맞벌이 · 행복주택 = `pct_dual 120` + 가산 `10` = **130** → `by_household["2"]["130"]`.
이 도구의 기본 가구원수는 2 이고, 해당 정책들은 `confidence: official` 이라 **어떤 강등 게이트에도 걸리지 않는다.**
즉 가산 누락은 원칙 9로도 막히지 않고 그대로 "불가"로 나간다.

- 표에 해당 **가구원수 또는 적용비율** 키가 없으면 `100% × 적용비율 ÷ 100` 폴백을 쓰고 **그 기준에** `근사값` 을 단다.
  100% 값조차 없으면 판정하지 않고 **`조건부 — 기준액 미확보`** 로 처리한다.
- 🔴 **근사값 기반 판정은 "불가"를 내지 않는다.** 폴백으로 만든 기준액에 걸려 탈락하는 경우
  `조건부 — 기준액 근사값(공표표에 해당 비율 없음). 공고문·기관 확인 필요` 로 강등한다. **"해당"은 그대로 허용한다.**
  이 비대칭은 의도된 것이다. 잘못된 "해당"은 사용자가 공고문을 열어보는 과정에서 바로잡히지만,
  잘못된 "불가"는 신청 포기로 끝나 되돌릴 수 없다. `confidence != "official"` 이 불가를 막는 것과 같은 이유다(원칙 9).
- **근사값 강등은 `기준 단위` 다**(D11). 정책 전체를 한꺼번에 강등하지 않는다 —
  그러면 유주택 같은 하드 불가 사유가 근사값 소득 사유에 삼켜져 사유 텍스트에서 사라진다.
- **2인 가구 100~140% 는 확보되어 있으므로**, 기본 입력(가구원수 2)에서는 공급형 정책이 정상 판정된다.
  단 **가산이 반영된 적용비율**(행복주택 = 110% / 맞벌이 130%)이 표에 있어야 한다(D2).
- `pct_dual` 이 `null` 이면 맞벌이여도 `pct` 를 쓴다.

**정책 판정 결합 순서** (D11) — 기준을 하나씩 평가한 뒤 **정책 단위로 합친다. 첫 사유에서 멈추지 않는다.**

1. 모든 기준(`income` / `total_asset_limit` / `net_asset_limit` / `car_value_limit` / `savings_months_min` / `savings_count_min` /
   `no_home_required` / 혼인 기간 / `age_max` / `region`)을 각각 **충족 · 조건부 · 불가** 로 평가하고, 각 결과에 `근사값` 여부를 함께 기록한다.
2. `confidence == "official"` **이고** `근사값` 이 아닌 **불가** 사유가 하나라도 있으면 → 정책 판정 = **불가**.
   사유는 **해당하는 불가 기준 전부**를 나열한다.
3. 그 외에 **조건부** 사유(값 미입력 · 근사값 강등 · 비official 강등 · `pending_change` 강등 · 추가 확인)가 하나라도 있으면 → **조건부**.
   사유 **전부**를 나열한다.
4. 전 기준 충족이면 → **해당**.

게이트(비official · `pending_change` · 근사값)는 **"불가 → 조건부" 강등만** 한다.
강등의 원인 문구는 지우지 않고 사유 뒤에 **`참고:`** 로 남긴다 — 사용자가 무엇 때문에 걸릴 수 있는지 알아야 공고문을 열어 확인한다.
예: `조건부 — 총자산 미입력 / 참고: 부부 합산 소득이 기준 초과(기준액이 근사값이라 불가로 판정하지 않음)`

**정책 자산 판정**: `total_asset_limit` / `net_asset_limit` / `car_value_limit` 각각을 대응 입력값과 개별 비교한다.
정책 유형별로 한도가 다르므로(행복주택 자동차 4,542만원 ↔ 국민임대 3,708만원) **하나의 필드로 합치지 않는다.**
입력값이 없으면 그 항목은 `조건부` 사유로만 남기고 불가로 만들지 않는다.

**혼인 판정** (D5) — 탭1 `혼인(예정)일` 하나로 **기혼**과 **예비신혼**을 갈라 판정한다.
이 도구는 결혼 후에도 계속 쓰이므로 기혼 경로를 비워 두면 반드시 잘못된 "해당"이 난다.

*입력일이 과거(또는 오늘) = **기혼***
- 혼인기간(개월) = **오늘 − 혼인일**
- `criteria.marriage_within_months` 가 `null` → 기간 제한 없음. 충족
- 정수 `N` 이고 혼인기간 ≤ `N` → **충족**
- 정수 `N` 이고 혼인기간 > `N` → **불가**. 사유 `혼인 기간 N년 초과`
  이것은 `confidence: official` 정책의 **공고 원문에 명시된 기준**이므로 "불가"를 낸다(§3-2 결합 순서 2단계).
  게이트 3종(비official · `pending_change` · 근사값)에는 걸리지 않는다 — 근거가 추정이 아니라 원문이다.

*입력일이 미래 = **예비신혼***
- `pre_marriage_allowed == false` → **조건부**. 사유 `예비신혼 불인정 정책 — 혼인신고 후 신청 가능`. **불가로 만들지 않는다**
- `pre_marriage_within_months` 가 `null` → 기간 제한 없음. 혼인 예정만 확인
- 정수 `N` → 오늘부터 혼인 예정일까지 남은 기간을 **일수 기준**으로 환산한 개월 수가 `N` 이하일 때만 충족.
  초과면 **조건부**(`예비신혼 인정 기간 초과 — 공고문 확인`). 월 번호만 빼서 계산하면 최대 1개월 관대해진다

*입력 없음* → 혼인 관련 기준은 전부 `조건부` 사유로만 남긴다. 정보 부재를 탈락으로 처리하지 않는다.

### 3-3. 실거래 분류 규칙

| 분류 | 조건 |
|---|---|
| **전세** (`jeonse`) | 월세 = 0 |
| **반전세** (`banjeonse`) | 월세 > 0 **이고** 보증금 ≥ 월세 × `banjeonse_ratio`(기본 240) |
| **월세** (`wolse`) | 그 외 |

- `banjeonse_ratio` 240은 통용 구분을 참고한 **설정값**이며 공식 출처를 확정하지 못했다. 변경 가능하도록 `config.json` 에 둔다.
- 주택유형 `housing_type` 은 `apt`(아파트) / `villa`(연립다세대) / `officetel`(오피스텔) 3종.
- **집계 키 = `station_id` + `housing_type` + `deal_type`.** 유형을 섞은 중위값은 만들지 않는다.
  아파트와 오피스텔 전세가 한 중위값에 섞이면 역별 비교가 통째로 왜곡된다.

### 3-4. 역 ↔ 법정동 매핑

**매핑표는 손으로 작성한다.** 계산으로 만들지 않는다.

1. 법정동 **경계 폴리곤·중심 좌표를 제공하는 출처가 조사서에 없다**(역 위경도와 법정동 코드만 있음).
   따라서 **"역 반경 약 1km"는 계산식이 아니라 작성자를 위한 수기 지침**이다. 거리 계산 코드를 만들지 않는다.
2. 13개 역 각각에 대해 생활권으로 인접한 법정동을 손으로 골라 `config.json` 의 **`stations: [{id, name, gu, dongs}]`**
   (1호선 순서 배열)에 넣는다. `build.py` 가 이 배열을 `meta.config.stations` 로 복사하고, 화면은 그 순서로 정거장 수를 계산한다(D18).
   역 목록·필드명을 화면 쪽에서 따로 발명하지 않는다.
3. **복수 역에 중복 매핑 허용.** 인접 역은 생활권이 겹치므로 배타 분할하면 오히려 왜곡된다.
   따라서 역별 계약 건수의 합은 전체 계약 건수보다 클 수 있다. **이건 버그가 아니다.**
4. 어느 역에도 매핑되지 않은 법정동의 계약은 집계에서 제외하고, 제외 건수를 `meta.excluded_trade_count` 에 기록한다.
5. 초안 작성 후 **사용자 검토 1회**를 받는다(생활권 감각은 거주 예정자만 판단 가능).
6. 매핑 근거는 `docs/DATA_SOURCES.md` 에 남긴다.

### 3-5. 수집 구조

```
collect.py  → 마이홈 공고 API + LH 분양임대공고문 조회 API(15058530) + 실거래 3종 호출
            → data/notices_manual.json (수동 등록분) 병합 — 같은 id면 수동분이 자동분을 덮어쓰고 detail_level 을 detailed 로 승격
            → data/notices.json, data/trades.json, data/meta.json 갱신
            → data/notices_prev.json 과 비교 → data/snapshot_diff.json, data/diff_history.json
            → data/notices_prev.json 을 이번 결과로 교체
build.py    → 위 JSON + data/policies.json + data/income_tables.json + config.json → site/index.html 단일 파일 생성
```

**자동화**
- GitHub Actions cron **`0 22 * * *` (UTC) = 매일 07:00 KST**.
  Actions cron은 UTC 기준이고 러너 혼잡 시 수십 분 지연이 흔하다. **화면의 "N시간 전"은 스케줄이 아니라 `generated_at` 실측값으로만 계산한다.**
- 개별 수집기 실패가 전체를 중단시키면 안 된다. **수집기 단위로 try/except 하고 `meta.collectors[]` 에 상태를 남긴다.**
- API 키는 저장소에 넣지 않는다. GitHub Actions Secrets 사용.
- 개인 조건은 브라우저에만 있으므로 저장소·산출물에 들어가지 않는다.

**🔴 API 키 마스킹 규칙** (D7) — 공개 저장소의 **Actions 로그와 커밋된 JSON 은 둘 다 공개다.**
"키를 저장소에 넣지 않는다"만으로는 이 경로가 막히지 않는다.

- 로그·`meta.collectors[].error`·예외 문자열에 남기기 전에 **`serviceKey=` 이후를 `***` 로 치환한다.** 쿼리스트링 전체를 잘라도 된다.
- **요청 URL 원문을 어디에도 출력하지 않는다.** `urllib` 예외(`HTTPError`/`URLError`)는 문자열화하면 URL 을 그대로 노출하므로
  **예외를 그대로 `str()` 해서 저장하지 않는다.** 예외 클래스명 + 상태코드 + 마스킹된 메시지만 남긴다.
- 디버그 `print` 도 같은 규칙을 따른다. 마스킹은 **저장·출력 지점 한 곳을 함수로 두고** 전 수집기가 그 함수를 지나게 한다.
- 검수: `data/*.json` · 빌드 산출물 · Actions 로그에 **키 패턴 0건**(§4).

**키가 없는 환경 — `--fixture` 오프라인 수집 경로** (D23)

- `DATA_GO_KR_KEY` 가 없으면 각 수집기는 예외로 죽지 않고 `status: "skip"`, `error: "DATA_GO_KR_KEY 없음"` 을
  `meta.collectors[]` 에 남기고 **직전 데이터를 그대로 유지한다**(원칙 4·7).
- `data/fixtures/` 에 **API 응답 형태의 샘플**을 둔다(수집기별 1개 이상). **`python collect.py --fixture`** 는
  HTTP 호출 없이 이 파일들을 응답으로 읽어 파싱·병합·diff 경로를 실제와 같게 태운다.
- `--fixture` 산출물의 `collectors[].kind` 는 실제 태그를 유지하되 `note` 에 `fixture` 를 적어 실데이터와 구분한다.
- **키 발급 전에도 `build.py` 와 §4 검수가 돌아가야 한다.** fixture 는 그 전제를 만드는 장치이며,
  개발 착수가 사용자의 활용신청(§7-1)에 묶이지 않게 한다.

**LH 공고 수집 규칙 (분양임대공고문 조회 서비스)** — D1

- 자동 수집 출처는 **"한국토지주택공사_분양임대공고문 조회 서비스"(데이터셋 15058530,
  `apis.data.go.kr/B552555/lhLeaseNoticeInfo1/lhLeaseNoticeInfo1`)** 다.
  **청약센터 공지사항 API(15058449)는 후보에서 제외한다** — 전국 게시판 메타데이터라 지역 필터가 없고
  "새 소식"이 매일 전국 공지로 넘친다(경보 피로). v1.1 이 이 API 를 전제로 쓴 문장은 전부 폐기됐다.
- **요청 파라미터**: `CNP_CD`(지역코드 = **부산**) · `UPP_AIS_TP_CD`(**`06` 임대주택**, 필요 시 **`39` 신혼희망타운** 추가) ·
  `PAN_SS`(공고상태) · `PAN_NT_ST_DT` · `CLSG_DT`(둘 다 **요청 전용 필터·필수**, `YYYY.MM.DD`. 응답에는 없다 — `DATA_SOURCES` §E-1).
  **부산(`CNP_CD=26`, 코드표 원문 미확인)과 `전국` 두 축을 모두 조회**해 합친다. `CNP_CD_NM` 이 "전국"인 공고를 부산 필터가 떨어뜨리면 매입·전세임대 전국 공고가 통째로 빠진다.
- **응답에서 쓰는 필드**: `PAN_NM`(공고명 → `title`) · `AIS_TP_CD_NM`(세부유형 → `supply_type`) ·
  `CNP_CD_NM`(지역명 → `sigungu_name` 후보) · `PAN_SS`(공고상태 → `notice_status`) ·
  `DTL_URL`(상세 URL → `source_url`). **`PAN_ID` 는 응답 필드가 아니라 `DTL_URL` 에서 파싱**한다(`gv_param=…,PAN_ID:0000059133` 형태와 `?panId=2015…` 형태 2종, 실패 시 복합키 폴백).
  즉 **제목·유형·지역·공고상태·상세URL까지 자동**이고 `apply_start`/`apply_end`/`announced_at` 은 **null**(수동 등록으로만 채움) — LH 자동수집분에는 D-day 가 없고 `notice_status`(`PAN_SS` 매핑)로 접수중·마감을 표시한다.
- 🔴 **금액·면적은 아직 자동이 아니다.** 짝 API "분양임대공고별 상세정보 조회"(15057999,
  `lhLeaseNoticeDtlInfo1/getLeaseNoticeDtlInfo1`, `PAN_ID` 필수)에 임대보증금·월임대료·전용면적 필드가 있는지
  **실호출로 확인되지 않았다**(`DATA_SOURCES` §E — 병행 조사 중).
  **확인 전까지 LH 공고는 `detail_level: "meta_only"` 를 유지**하고 상세는 `notices_manual.json` 수동 등록에 의존한다.
  상세 API 응답에 금액 필드가 확인되면 그때 `detailed` 자동 승격 규칙을 이 절에 추가한다 — **확인 후 확정**.
- 신선도 바의 LH 태그는 여전히 **반자동**이다(금액·면적 수동). 태그를 `자동` 으로 올릴 조건은 상세 API 확인 하나뿐이다.
- 🔴 **공고문 본문·자유서식에서 금액·면적을 정규식으로 긁어내지 않는다.** 서식이 고정돼 있지 않아 오파싱이 조용히 섞인다.
  **잘못된 금액은 빈 금액보다 나쁘다** — 예산 판정을 오염시키고, 사용자는 그것이 틀렸는지 알 수 없다.
- `PAN_SS` 가 `접수마감` 이면 `apply_end` 와 무관하게 **마감(`closed`)** 으로 다룬다(D12).
- **LH는 금액 상세가 없어도 "새 소식"의 신규 공고 알림은 정상 동작한다.**

**실거래 재수집 규칙**
- 계약 후 30일 이내 신고 가능해 최근 데이터는 계속 추가·정정된다.
- **매일 최근 2개월 구간(`DEAL_YMD` 당월·전월)을 재수집하고, 그 이전 구간은 캐시를 재사용한다.**
- **호출은 `numOfRows=1000` 으로 하고 `pageNo` 를 1부터 `totalCount` 를 넘을 때까지 순회한다**(D15).
  기본값이 10건이라 페이징을 빼먹으면 구·월당 수백 건 중 앞 10건만 집계된다 — 중위값과 히스토그램이 통째로 틀어진다.
- 3개 시군구 × 3개 주택유형 × 2개월 = **회당 18개 구간**(구간마다 페이지 수만큼 호출). 개발계정 한도(일 10,000건) 대비 여유.
- **첫 실행 백필 = `trade_months` 전체 구간**(기본 12개월 → 3 × 3 × 12 = 108개 구간 + 페이지). 이후 실행부터 최근 2개월만 재수집한다.
- 이번 실행에서 재수집한 구간은 **`trades.refetched_months` 에만** 남긴다(`meta` 에 중복 두지 않는다, D21).

**공고 신규·마감 판정 규칙** (D8·D12)

- **`first_seen`** — `notices_prev.json` 에 같은 `id` 가 있으면 그 값을 **승계**하고, 없으면 **오늘 날짜**를 넣는다.
  승계 규칙이 없으면 값이 매일 갱신되어 탭2 "최근 7일 신규" 창이 만들어지지 않는다.
- **`closed`(마감) 정의** = `apply_end < today` **또는** 이번 수집의 출처 목록에서 **소멸**한 공고.
  소멸한 경우는 **`disappeared: true`** 로 구분해 화면 문구를 `출처 목록에서 사라짐(마감 추정)` 으로 다르게 적는다.
  LH `PAN_SS` 가 `접수마감` 이면 `apply_end` 와 무관하게 마감이다.
- `apply_end` 가 `null` 인 공고(`meta_only` 다수)는 **D-day 를 계산하지 않는다.** `null` 을 임박으로 취급하지 않는다.
  이 공고는 출처 목록에서 사라질 때만 마감으로 넘어간다.
- **마감 임박의 정본 2종** — 탭2 고정 섹션은 **오늘 기준 D-30 이내 전체**(매일 재계산),
  탭5 `closing_soon` 은 **이번 수집에서 새로 D-30/D-7 안으로 들어온 것**.
  둘의 건수가 다른 것은 정상이며 각 화면 캡션에 무엇을 세는지 적는다. `closing_soon[].dday` 는 탭5 화면에서 그대로 표시한다.

**공고 식별키 (`notices.id`)**
- 1순위: `{source}:{공고번호}` — API가 공고번호를 주는 경우
- 폴백: `{source}:{supply_type}:{apply_end}:{sigungu_code}` 복합키의 해시.
  충돌하면 접수시작일을 덧붙이고, 그래도 충돌하면 정규화한 제목을 덧붙인다.
- **제목만으로 키를 만들지 않는다.** 원문 제목이 한 글자만 고쳐져도 매일 "신규 공고" 오탐이 난다.
- 어느 방식을 썼는지 `id_basis: "notice_no" | "composite"` 로 남겨 QA가 확인할 수 있게 한다.

**정책 변경 감지 (오탐 대비)**
- 해시 대상은 페이지 전체가 아니라 **`content_id` 로 지정한 본문 영역**이다.
- 🔴 **`content_id: string|null` 은 `#id` 하나만 받는다**(D14). CSS 선택자 문법을 지원하지 않는다 —
  표준 라이브러리 `html.parser` 에는 선택자 엔진이 없고(원칙 2), 선택자를 직접 구현하면 범위가 조용히 넓어진다.
  `id` 속성이 일치하는 **첫 요소의 텍스트만** 모아 해시한다.
- `content_id` 가 `null` 이거나 그 `id` 를 찾지 못하면 페이지 전체 텍스트에서 **공백·숫자·날짜 패턴을 제거한 뒤** 해시한다
  (방문자 수·갱신일 배너 때문에 매일 변경으로 잡히는 것 방지).
- 가져오기 자체가 실패하면(UA 차단·JS 렌더 등) **해시를 갱신하지 않고** 그 수집기를 실패로 표시한다(원칙 4). `kind` 는 `semi` 를 유지한다.
- 같은 변경은 **1회만 알림**한다. `last_notified_hash` 와 같으면 다시 띄우지 않는다.
- 경보 피로가 쌓이면 진짜 변경을 놓친다.

**`data/income_tables.json`** — 연 1회 갱신. **가구원수 × 비율** 2차원 구조.
```
{ urban_worker: {
    year_label: string,        // 공표년도 라벨. 예 "2026년도 적용기준(2025년 실적)" (D13)
    source_url: string,
    verified_at: string,
    confidence: "official"|"secondary"|"unverified",
    by_household: {            // 키 = 가구원수, 값 = 비율별 월 기준액(원)
      "2": { "100": int, "110": int, "120": int, "130": int, "140": int },
      "3": { ... }, "4": { ... }, ...
    } },
  median_income: { year_label, source_url, verified_at, confidence, by_household: { ... } },
  //   ↑ 2026 보건복지부 고시 기준중위소득으로 채운다 (연구자 담당, D4).
  //     비어 있으면 basis: median_pct 정책(통합공공임대)이 전부 `조건부 — 기준액 미확보` 로 남는다
  updated_at: string }
```
- 값 단위는 **원(월)**. 정책이 요구하는 비율(`pct`/`pct_dual`)을 **표에서 직접 조회**한다.
- **비율을 100% 값에 곱해서 만들지 않는다.** 공표표의 비율별 금액은 반올림 처리가 들어가 곱셈 결과와 어긋날 수 있다.
  표에 그 비율 키가 없을 때만 `100% × 비율 ÷ 100` 을 폴백으로 쓰고, 그 카드에 `근사값` 표시를 단다.
- **`year_label` 을 정책 카드에 함께 노출한다.** 적용년도와 실적년도가 1년 차이라 사용자가 "올해 값인가"를 반드시 묻게 된다.
  위 예시 `"2026년도 적용기준(2025년 실적)"` 은 **D13 의 예시값**이다 — 원문 페이지마다 라벨 표기가 달라
  (`DATA_SOURCES` §D-3: LH청약플러스 "2025년도 기준" ↔ jpdc·i-sh "2026년") 최종 문구는 **연구자가 원문 병기 문구를 직접 확인해 확정한다.**
  라벨을 잘못 붙이면 맞는 값이 틀린 값으로 보이고, 사용자는 다른 연도 표를 찾아 헤맨다.
- 해당 가구원수 키가 없거나 필요한 비율을 만들 수 없으면 판정하지 않고 `조건부 — 기준액 미확보` 로 처리한다.
- **2인 가구(예비신혼부부의 기본값) 100~140% 는 확보되었다**(`DATA_SOURCES` §D-3). 다른 가구원수는 확보된 범위만 채운다.

## 5. 범위 밖 (v1 비목표)

명시적으로 **하지 않는다**. 나중에 하고 싶어지면 별도 결정 후 v2로 올린다.

1. **민간 매물 수집** — 공식 API 없음 + 이용약관 크롤링 금지. 역·거래유형만 담은 검색 링크로 대체.
2. **로그인·계정** — 개인 1인용. 인증 구조 자체를 두지 않는다.
3. **알림 발송** — 메일·카톡·푸시 없음. "새 소식" 탭을 사람이 열어서 본다.
4. **매매 · 매매 시세** — v1 제외. 입력 항목도 노출하지 않는다. LTV·DSR이라는 별도 판정 축을 끌고 들어온다.
5. **부산도시공사 임대주택현황 API** — 공고가 아니라 **현황 통계**(유형별 공급 세대수·소재 구군)이므로 공고 출처가 아니다.
6. **청약 신청·자격 확정 판정** — 이 도구의 자격 판정은 **참고용 사전 대조**이지 공식 판정이 아니다.
   화면에 이 문장을 명시한다. 최종 판단은 반드시 공고 원문·기관 문의로 한다.
7. **지도 표시** — 지도 타일은 외부 리소스라 원칙 1과 충돌한다. 1호선 노선도식 가로 띠로 대체.
8. **부산 1호선 외 노선** — 2·3·4호선, 동해선, 부산김해경전철 제외.
