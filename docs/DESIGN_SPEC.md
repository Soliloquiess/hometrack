### 1-3. 타이포 · 단위

| 역할 | 규격 |
|---|---|
| body | 14px / 1.55 / `--sans` |
| h1 20px · h2 14px `--fg-2` | |

| 캡션 | 11.5~12px / `--fg-3` |

🔴 **단위가 두 종류다. 섞으면 1만배 오차가 난다.**

| 대상 | 단위 | 함수 | 출력 예 |
|---|---|---|---|
| 공고 보증금 · 예산 · 자산 | **만원** | `won()` | `2억 1,000만원` |
| 월임대료 · 월세 상한 | **만원** | 직접 | `18만원` |
| 소득 기준액 (`income_tables`) | **원(월)** | `krwMonth()` | `5,760,000원` |
| 연소득 입력 | **만원** | `won()` | `6,000만원` |

연소득을 월평균으로 바꿀 때만 `연소득 × 10000 ÷ 12` 로 원 단위에 맞춘다.
**이 변환은 소득 판정 한 곳에만 둔다.** 여러 곳에 흩어지면 어디서 1만배가 어긋났는지 찾을 수 없다.

**소득 기준액은 가구원수 × 비율 2차원 표에서 직접 읽는다** (SPEC §3-6).

```
기준액 = income_tables[basis].by_household[가구원수][적용비율]
적용비율 = 맞벌이면 pct_dual, 아니면 pct
```

| 표 조회 결과 | 화면 |
|---|---|
| 해당 비율 칸이 있음 | 그 값을 그대로 쓴다. 표시 없음 |
| 비율 칸은 없고 `100%` 는 있음 | `100% × 비율 ÷ 100` 폴백 + **`근사값` 칩** |
| `100%` 도 없거나 가구원수 행이 없음 | 판정하지 않고 `조건부 — 기준액 미확보` |

🔴 **비율을 100% 값에 곱해서 만들어 놓고 근사값 표시를 빼면 안 된다.**
공표표는 비율별로 반올림이 들어가 곱셈 결과와 어긋난다. 어긋난 값을 정확한 값처럼 보여주는 것이 가장 나쁘다.
`year_label`(예: `2025년도 적용기준(2024년 실적)`)을 **적용액 옆에 항상 함께** 찍는다.
적용년도와 실적년도가 1년 차이라 사용자가 "올해 값인가"를 반드시 묻게 된다.

## 2. 공통 컴포넌트 카탈로그

### 2-1. 신선도 바 `.fresh` — **출처별 6줄**. 묶지 않는다.

```
┌ 데이터 신선도 — 출처별로 갱신 주기와 방식이 다릅니다 ────────────────┐
│▎공고 · 마이홈포털   3시간 전 · 5건       스키마 확인 전까지 [반자동]│
│▎공고 · LH           감지 3시간 전 · 신규 2건   원문 목록 ↗   [반자동]│
│                     상세 등록 2026-09-01          ← .v2 둘째 줄      │
│▎공고 · 부산도시공사 직전 성공 09-01 · 3건  청약센터 개편 [실패·수동]│ ← --hi
│▎전월세 시세         호출 3시간 전 · 최신 계약월 2026-08     [자동]│
│▎정책·지원           정리 2026-08-28 · 점검 3시간 전       [반자동]│
│▎민간 매물           수집 안 함 — 검색 링크만 제공              [—]│ ← 회색
└──────────────────────────────────────────────────────────────────────┘
※ 실거래 = 과거 계약 기록. 신고 지연 최대 30일.
   태그는 수집기가 보고한 값 그대로이며 화면에서 승격하지 않습니다.
```

- 한 줄 = `.row` (`.k` 출처명 / `.v` 시각·건수 / `.why` 사유·주석 / `.st` 태그).
- 🔴 **태그는 `meta.collectors[].kind` 를 그대로 찍는다.**
  `auto`→자동 · `semi`→반자동 · `manual`→수동 · `none`→—.
  마이홈은 응답 스키마가 확인될 때까지 `semi` 다.
  **화면에서 "자동"으로 올려 적으면 원칙 3을 스스로 어긴다.**
- 상태 색: `ok`→`--low` · `fail`→`--hi`(배경 `--hi-bg`) · `skip`→`--line-2`+`--fg-3`.
- **실패 줄에는 직전 성공 시각 + 실패 사유가 반드시 함께** 들어간다.
- 수동 줄에는 **원문 목록 링크**를 붙인다. 사람이 등록하러 갈 곳이 화면에 있어야 한다.
- 🔴 **LH 줄은 두 줄로 나눠 적는다**(`.v` + `.v2`).
  LH 공지사항 API 가 주는 것은 제목·부서·등록일뿐이고 **보증금·월세·면적·접수기간·대상 필드가 응답에 아예 없다.**

  | 줄 | 내용 | 뜻 |
  |---|---|---|
  | `.v` | `감지 3시간 전 · 신규 2건` | 새 게시물이 떴다는 사실은 자동으로 안다 |
  | `.v2` | `상세 등록 2026-09-01` | 금액·접수기간은 사람이 마지막으로 채운 날짜 |

  태그는 **`반자동`**. 한 줄로 뭉쳐 "자동"이라고만 적으면 사용자가 **금액까지 최신인 줄 오인한다.**
  원칙 3이 막으려는 바로 그 사고다. `.why` 에 "신규 게시물 감지는 자동, 공고 내용은 수동"을 명시한다.
- "N시간 전"은 스케줄이 아니라 `meta.generated_at` 실측값으로 계산한다(cron 지연 때문).

### 2-2. 판정 뱃지 · 신뢰도 뱃지

**판정 `.verdict` — 3단 + 사유 (사유 없는 뱃지 금지)**

```
[해당]  · 예비신혼부부 대상 · 통합공공임대 소득·자산 기준 충족     ← --low
[조건부] · 총자산·자동차 가액 미입력                                ← --mid
[불가]  · 부부 합산 소득이 기준 초과 (6,000만원 > 5,500만원)       ← --hi
```

**신뢰도 `.conf` — 정책 카드 전용 3단**

| 값 | 뱃지 | 색 | 판정에 미치는 영향 |
|---|---|---|---|
| `official` | 공식 출처 | `--bg-3` / `--fg-2` | 정상 3단 판정 |
| `secondary` | 2차 자료 | `--mid` | **불가 금지** → `조건부 — 수치 미검증` |
| `unverified` | 미검증 | `--hi` | **불가 금지** → `조건부 — 수치 미검증` |

🔴 **`official` 이 아닌 정책은 어떤 값이 들어와도 불가를 띄우지 않는다.**
강등할 때 원래 판정을 버리지 않고 뒤에 붙인다:

```
조건부 — 수치 미검증(2차 자료 기준). 공고문 확인 필요 —
        참고: 부부 합산 소득이 기준 초과 (6,000만원 > 5,000만원)
```

검증되지 않은 숫자로 사용자가 신청을 포기하면 실손해가 난다.
카드 안에도 같은 취지를 한 줄 적어, 왜 불가가 안 뜨는지 화면에서 읽히게 한다.

**불가를 막는 장치가 하나 더 있다 — 근사값** (SPEC §3-2)

소득 기준액을 공표표에서 직접 못 읽고 `100% × 비율` 로 폴백했다면,
**그 기준액에 걸린 탈락은 불가로 내지 않는다.** 문구는 SPEC 원문 그대로 쓴다.

```
조건부 — 기준액 근사값(공표표에 해당 비율 없음). 공고문·기관 확인 필요 —
        참고: 월평균 소득 5,000,000원이 기준 4,320,000원 초과 (2인 · 90% · 근사값)
```

🔴 **"해당"은 근사값이어도 그대로 허용한다. 이 비대칭은 의도된 것이다.**
잘못된 "해당"은 사용자가 공고문을 열어보는 과정에서 바로잡히지만,
잘못된 "불가"는 신청 포기로 끝나 되돌릴 수 없다. `confidence` 게이트와 같은 이유다.

| 불가를 막는 장치 | 조건 | 강등 후 문구 |
|---|---|---|
| `confidence` | `official` 이 아님 | `조건부 — 수치 미검증(… 기준). 공고문 확인 필요 — 참고: …` |
| **근사값** | 기준액이 폴백 계산분 | `조건부 — 기준액 근사값(공표표에 해당 비율 없음). 공고문·기관 확인 필요 — 참고: …` |

둘 다 **원인 문구를 버리지 않고 `참고:` 뒤에 남긴다.** 사용자가 "얼마가 모자란지"는 알아야 한다.

🔴 **`null` 이 정상 케이스다**(SPEC v1.1 #1). 빈 값을 오류로 취급하지 않는다.

| 필드 | null 일 때 |
|---|---|
| `deposit_*` · `rent_*` | `공고문 확인 필요` 칩(`.chip-mask`) + **예산 판정 없음** |
| `area_*` | `미표기`(`--fg-3`) |
| `supply_type` | `유형 미표기` |
| `apply_start`/`end` | `접수기간 미표기` |
| `station_ids` 빈 배열 + `sigungu_code` 있음 | `역 매핑 없음` 칩 |
| `station_ids` 빈 배열 + `sigungu_code` 도 `null` | `지역 미표기` 칩. **지역 필터로 떨어뜨리지 않는다**(아래) |
| `target_groups` 빈 배열 | `미표기` + 판정은 **조건부**(불가 아님) |

**`detail_level` — 카드가 얼마나 채워졌는지** (SPEC 723줄 델타)

| 값 | 배지 | 뜻 |
|---|---|---|
| `detailed` | 없음 | 금액·면적·접수기간이 (있는 만큼) 채워진 공고 |
| `meta_only` | **`상세 미수집`** (`.fit-meta`, 점선) | 제목·등록일·링크만. LH 자동수집분의 기본값 |

`meta_only` 카드에는 배지 아래 한 줄로 이유를 적는다:
*"출처 API 가 제목·등록일·링크만 제공합니다. 금액·면적·접수기간·대상은 원문을 열어 확인하고,
필요하면 수동 등록으로 상세를 채웁니다."*

- `meta_only` 는 금액이 `null` 이므로 자동으로 **금액 미표기 묶음**에 들어간다. 예산 밖이 아니다.
- 사람이 `notices_manual.json` 에 상세를 채우면 `detailed` 로 승격되어 예산 판정 대상이 된다.
- 🔴 **지역 정보가 아예 없는 공고(`station_ids` 빈 배열 + `sigungu_code` null)는 지역 필터로 떨어뜨리지 않는다.**
  정보 부재를 탈락으로 처리하면 §3-2 가 경계하는 바로 그 사고가 난다.
  구 코드는 있는데 역 매핑만 없는 공고(사하구 등)는 정상적으로 걸러진다.

**예산 2단 칩 `.fitchip`** (SPEC §3-1 — 공고는 범위값이라 2단)

| 조건 | 칩 | 색 |
|---|---|---|
| `deposit_max <= 가용액` | `전 평형 가능` | `--low` 실선 |
| `deposit_min <= 가용액 < deposit_max` | `일부 평형 가능` | `--low` 점선 |
| 금액 `null` | `예산 판정 없음 · 임대보증금 미표기` | `--fg-2` |
| `deposit_min > 가용액` | **`예산 밖`** (`.fit-over`, `--hi`) + 사유 한 줄 | `--hi` |

🔴 **예산 밖 카드에도 칩을 단다.** 목록에는 그리지 않지만 **인쇄하면 접힘이 펼쳐지므로**,
카드 자체가 "예산 밖"임을 스스로 말하지 않으면 예산 내 목록과 구분 없이 섞여 나온다.
`.fold` 라벨과 이 칩 **둘 다** 있어야 한다. 하나만으로는 인쇄물에서 구분이 사라진다.

- 카드 좌측 3px 세로 바로 판정색을 반복(목록 훑기용). 텍스트 뱃지가 항상 우선.
- 출처 줄에 **자동/수동 태그**와 **식별키 종류**(`공고번호 키` / `복합키`)를 적는다.
  키 오탐("매일 신규 공고로 잡힘")을 QA 가 눈으로 확인할 수 있게.
- 원문 링크는 `target="_blank" rel="noopener noreferrer" referrerpolicy="no-referrer"`.

### 2-5. 실거래 요약 카드 `.trade-sum` — 거래유형 3줄

```
┌ 구서 · 아파트 · 최근 12개월                          [기준역] ┐
│ 전세   1억 9,500만원        84건                              │
│        내 예산 이내 61%     ▉▉▉▉▉▉░░░░                        │
│ 반전세 9,400만원 / 월 30만원  21건   [환산 1억 5,400만원]      │
│ 월세   1,800만원 / 월 40만원  46건   [환산 9,800만원]          │
└───────────────────────────────────────────────────────────────┘
```

- 🔴 **집계 키 = `station_id` + `housing_type` + `deal_type`.**

- 줄별 상태:
  - 표본 `< sample_min` → `표본 부족 (N건)` + 작게 `참고값 …` (`--mid`).
    중위값을 대표값으로 내세우지 않는다.
  - 표본 0건 → `해당 기간 신고된 계약 없음` (`--fg-3`).
- **예산 내 비율은 전세 줄에만** 붙인다.
  반전세·월세는 `환산` 칩으로 전세환산액을 병기하되 실계약액과 섞지 않는다.
- 카드 순서는 **기준역에서 가까운 순**(정거장 수 오름차순), 최대 6개.
  라인 순서로 앞에서 자르면 정작 판단이 갈리는 기준역 주변 역이 화면에서 빠진다.

**거래유형 분류**(SPEC §3-3)는 수집기가 정한다. 화면은 분류 결과를 표시만 한다.
`전세` = 월세 0 / `반전세` = 월세 > 0 이고 보증금 ≥ 월세 × `banjeonse_ratio` / `월세` = 그 외.


- 이 블록은 항상 목록 **하단**. 위로 올리면 "이 도구가 매물을 준다"는 오해를 만든다.

**입력 사양** — 필수 8 / 선택 5

|---|---|---|---|

값은 지우지 않고 그대로 두되 판정에서만 제외한다. **입력 중에 화면이 죽으면 안 된다.**

**상단 고정 섹션** — 지역 필터를 걸면 신규가 0건인 날이 많다. 그래도 매일 열 이유가 남아야 한다.

- `신규` = `first_seen` 이 7일 이내이고 마감 전인 공고 (`--add-*`)
- `마감 임박` = D-30 이내. D-7 이내는 `--hi`, 그 밖은 `--mid`
- 0건이어도 **블록을 숨기지 않는다.** `최근 7일 신규 공고 없음` 한 줄로 남긴다.
- **조건 미입력 상태에서도 표시한다.** 예산과 무관하게 유효한 정보다.

**공고 자격 판정 — `linked_policy_id` 승계** (SPEC §3-2, **정식 필드**)

`notices.json` 에는 소득·자산 기준 필드가 없다. 공고 API 가 주지 않기 때문이다.
그래서 `linked_policy_id` 로 정책 판정을 승계한다. 값은 사람이 `notices_manual.json` 에서 지정하거나
공급유형 → 정책 매핑표(`config.json`)로 자동 부여한다.

| 조건 | 공고 판정 | 사유 문구 |
|---|---|---|
| `exclusions` 에 걸림 | **불가** | `공고 명시 배제 조건: 유주택 세대 제외` |
| 연결 정책이 **해당** | **해당** | `자격 기준 충족 (연결 정책: 행복주택)` |
| 연결 정책이 **조건부** | **조건부** | `연결 정책 판정에 총자산 미입력 (행복주택)` |
| 연결 정책이 **불가** | 🔴 **조건부** | `연결 정책 자격 미충족 (행복주택: 소득 기준 초과). 공고 기준은 다를 수 있으니 공고문 확인` |
| `linked_policy_id` 없음 | **조건부** | `연결된 정책 없음. 자격 대조 정보 없음` / 대상 표기만 있으면 `연결된 정책 없음. 대상 표기는 있으나 기준 대조 불가` |

🔴 **정책의 "불가"를 공고로 승계하지 않는다.**
공고마다 소득·자산 기준이 본 정책과 다를 수 있고(회차별 완화, 우선공급 별도 기준),
연결 자체가 사람이 붙인 **추정**이다. 추정 위에 얹은 탈락 판정은 근거가 두 겹으로 약하다.
공고에서 불가를 낼 수 있는 근거는 `exclusions` 하나뿐이다. 그건 공고 원문 자체가 근거다.

- **승계 시 어느 정책에서 온 판정인지를 사유에 반드시 적는다.** 정책명 없는 승계 사유는 추적이 안 된다.
- 연결 정책의 `confidence` 가 `official` 이 아니면 **공고 카드에도 신뢰도 배지를 함께 단다.**
- `target_groups` 는 **표시용**이다. 원문 대상 표기를 그대로 보여주되 판정 근거로는 `linked_policy_id` 를 우선한다.

**목록 3묶음**

| 묶음 | 표시 | 이유 |
|---|---|---|
| 1. 예산 내 | 카드 + `전 평형` / `일부 평형` 칩 | — |
| 2. 금액 미표기 | 카드. **접지 않는다** | 판정 불가지 탈락이 아니다 |
| 3. 예산 밖 | `예산 밖 N건 접힘` 한 줄. 카드를 그리지 않는다 | `DESIGN.md` §3 |

**지역 필터** `13역 인근`(기본) ↔ `부산 전역`.
13역 결과가 0건이면 부산 전역 건수를 자동 안내하고 `부산 전역으로 보기` 버튼을 빈 상태 안에 둔다.

```
│ │ 않습니다 — 검증되지 않은 숫자로 신청을 포기하지 않기 위해서입니다│ │
└────────────────────────────────────────────────────────────────────┘
┌ 불가 (1) ─ 좌측 바 --hi · 기본 접힘 ───────────────────────────────┐
```

**정책 카드 필드**: 정책명 / 신뢰도 뱃지 / 판정 + 사유 / 제공기관 · 유형 / 혜택 /
**적용된 소득 기준값** / 자산 / 청약통장 / 비고 / `수동 정리` 뱃지 / 최종 확인일 / 근거 출처 링크.

⭐ **소득 줄에 3가지를 함께 찍는다** — 기준 비율 / 지금 내 가구원수·비율의 적용 금액 / `year_label`.
`기준 중위소득 100%(맞벌이 120%) 이하 · 2인 120% 적용액 5,160,000원  2026년 기준 중위소득`
비율만 적으면 사용자가 자기 숫자와 비교할 수 없다. 기준액이 없으면 `기준액 미확보`.

**`근사값` 칩**은 표에 그 비율 칸이 없어 `100% × 비율` 로 폴백했을 때만 붙인다(1-3).
칩에 `title` 로 "표에 이 비율 칸이 없어 100% 값에 비율을 곱했습니다"를 넣는다.

> ✅ **해소됨**: 앞선 검토에서 "근사값에 근거한 불가가 나올 수 있다"고 짚었던 문제는
> SPEC §3-2 가 **근사값 기반 불가 금지**를 규칙으로 확정하면서 해결되었다(2-2).
> 목업의 국민임대가 바로 그 사례이며, 지금은 `조건부 — 기준액 근사값(…)` 으로 강등된다.

**경고 3종** (겹치면 모두 표시, `--hi` 가 위)

| 조건 | 표시 |
|---|---|
| `source_hash != last_notified_hash` | `--hi` — 출처 본문이 바뀌었습니다. 무엇이 바뀌었는지는 사람이 확인해야 합니다 + 감지 영역 표기 |
| `verified_at` 90일 초과 | `--mid` — 확인한 지 N일 지났습니다 |
| `confidence != official` | `--mid` — 이 정책은 어떤 값을 넣어도 불가로 판정하지 않습니다 |

**상태**: 조건 미입력이어도 정책 카드를 감추지 않는다. 목록으로서의 가치가 있다.
상단에 `.banner.warn` 로 "조건을 입력하면 해당/불가로 갈립니다"만 붙인다.

  실제 구현을 가른다.

## 7. 목업 → 실데이터 교체 지점 · 미결

### 7-1. 교체 지점

- `mockup/index.html` 의 `var DATA = {…}` **한 블록**이 전부다.
  키는 SPEC §3-6 스키마 그대로:
  `meta.collectors[]` · `stations[]` · `notices[]` · `trades.aggregates[]` ·
  `income_tables` · `policies[]` · `diff`.
  `build.py` 는 이 블록만 JSON 으로 갈아끼우면 된다.
- **목업에만 있고 실 사이트에 없어야 하는 것** — 전부 `data-mock-only` 속성이 달려 있다.
  `grep -n 'data-mock-only' mockup/index.html` 로 제거 지점 3곳이 그대로 나온다.

  | 요소 | 속성값(제거 지침) |
  |---|---|
  | `.banner.mock` | 배너 — 실 사이트에서는 통째로 삭제 |
  | `#btn-sample` | 버튼 + `btn-sample` 핸들러 삭제 |
  | `#seg-news [data-news="first"]` | 버튼 삭제. `is_first_run` 은 데이터로 판단 |
- **목업이 갖지 않은 것**:
  역↔법정동 매핑 실표(역당 1~4개 예시 동만. 손으로 작성할 항목),
  실제 딥링크 쿼리 파라미터 문법(플레이스홀더 URL).

### 7-2. 스키마 공백 — 해소됨

`notices.json` 에 소득 기준이 없어 공고 "해당" 판정이 불가능하던 공백은
**`linked_policy_id` 가 SPEC §3-6 의 정식 필드로 승격되면서 해소되었다.**
목업 확장 필드가 아니다. 승계 규칙과 사유 문구는 3-탭2 참조.

같은 이유로 **`first_seen`(신규 판정용)도 목업 확장 필드**다.
`diff.new_notices` 는 하루치라 "최근 7일 신규"를 만들 수 없어 추가했다.
`notices.json` 에 넣는 편이 자연스럽다.

**참고**: `meta_only` 공고는 `target_groups` 가 비어 있어 자격 판정이 항상
`조건부 — 대상 미표기(공고문 확인 필요)` 다. 이건 정상 동작이다.
LH 감지 수집기의 값어치는 자격 판정이 아니라 **"새 공고가 떴다"는 알림**에 있다(SPEC §3-5).
