# hometrack 핸드오프

이 프로젝트의 진행 상태는 **저장소 안의 `CLAUDE.md` §9** 가 유일한 정본이다. 회사 PC 의 전역 메모리에 기대지 않는다.

## 절차
1. 이번 세션에서 한 일을 훑어 아래 네 묶음으로 정리한다. 전체 대화를 붙이지 말고 핵심만.
   - **완료**: 실제로 끝나고 검증된 것(QA 판정 포함). 검증 안 된 것은 "미검증"으로 표기
   - **사용자 결정·행동 대기**: 사용자만 할 수 있는 것(활용신청, 매핑 검토, 저장소 설정 등)
   - **다음 할 일**: 착수 순서대로 번호. 실행 명령·파일명 포함
   - **잔여 조사(미확인)**
2. `CLAUDE.md` 의 `## 9. 현재 상태` 절만 교체한다. §1~§8 은 규칙이 바뀐 경우에만 수정한다. "최종 갱신" 날짜를 오늘로.
3. 민감정보 점검: 커밋 대상에 API 키·토큰·개인정보(실명·직장명·연락처)·내부 IP 가 없는지 `git diff --cached` 로 확인한다. 개인 예산·소득 값도 저장소에 넣지 않는다.
4. `git add -A && git commit -m "handoff: <한 줄 요약>"` 으로 커밋한다. **push 는 하지 않는다.** 푸시 자격증명이 있는 PC 에서는 사용자 지시가 있을 때만 `git push` 한다. 없으면 사용자가 저장소 루트에서 `! git push` 로 직접 한다. 커밋 후 그 명령을 안내한다.
5. 사용자에게 갱신한 §9 내용을 그대로 보여준다.

## 주의
- `site/`·`data/` 의 자동 수집 결과가 이번 세션 변경에 섞여 있으면 별도 커밋으로 분리한다(`data: 2026-09-XX 수집분`).
- 검증되지 않은 것을 "완료"로 쓰지 않는다. QA 미실시면 "QA 대기"로.
